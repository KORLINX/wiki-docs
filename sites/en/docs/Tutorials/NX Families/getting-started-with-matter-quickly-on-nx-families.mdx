# Getting Started with Matter Quickly on NX Families

This tutorial is the shortest path from a connected NX development board to a commissioned Matter device.

You will flash a validated firmware package, commission the device over Bluetooth Low Energy, join it to a Thread network, and verify one Matter command. You do not need to build the firmware from source in this tutorial.

:::caution
Publication gate
Do not publish this tutorial until KORLINX provides a tested prebuilt firmware package, setup code, supported board list, flash procedure, LED and button behavior, and validated commissioner ecosystem.
:::

## What you will do

1. Download the validated Matter sample.
2. Connect the NX development board.
3. Erase and flash the firmware.
4. Confirm Bluetooth Low Energy advertising.
5. Commission the device using its QR code or manual pairing code.
6. Join the device to Thread.
7. Send a Matter command and confirm the device response.

## Step 1: Download and verify the firmware package

1. Download `[FIRMWARE_FILE]` from `[KORLINX_RELEASE_URL]`.
2. Confirm that the package supports your NX board and hardware revision.
3. Calculate the SHA-256 checksum.

On Linux:

```bash
sha256sum [FIRMWARE_FILE]
```

On macOS:

```bash
shasum -a 256 [FIRMWARE_FILE]
```

On Windows PowerShell:

```powershell
Get-FileHash [FIRMWARE_FILE] -Algorithm SHA256
```

4. Compare the result with the published checksum.

Do not flash the package if the checksum does not match.

## Step 2: Connect the NX development board

1. Disconnect external loads that are not required by the sample.
2. Connect the board to the development host using the approved USB or debug connection.
3. Open an SDK terminal.
4. Confirm that the device is detected:

```bash
nrfutil device list
```

5. Record the device identifier and serial port.

## Step 3: Erase and flash the prebuilt firmware

Use the validated KORLINX programming method.

### Using Programmer

1. Open **Programmer** in nRF Connect for Desktop.
2. Select the connected device.
3. Select **Add file** and open `[FIRMWARE_FILE]`.
4. Confirm that the memory layout is accepted.
5. Select the approved erase option.
6. Select **Write** or **Erase and Write**.
7. Wait for the programming and verification steps to complete.

## Step 7: Commission the NX device

The exact screens depend on the validated commissioner. The required flow is:

1. Open the selected Matter commissioner application.
2. Choose **Add device** or the equivalent command.
3. Scan the QR code or enter the manual pairing code.
4. Keep the NX device close enough for the Bluetooth Low Energy commissioning connection.
5. Select or confirm the target Matter fabric.
6. Allow the commissioner to transfer the Thread Operational Dataset.
7. Wait until the device joins the Thread network.
8. Assign the device name and room if the application requests them.

## Step 8: Verify the Matter command

Open the commissioned device in the selected controller and perform the function implemented by the sample.

For a light sample:

1. Send **On**.
2. Confirm that the assigned LED or load turns on.
3. Send **Off**.
4. Confirm that the assigned LED or load turns off.
5. Check the serial log for the corresponding application event.

## Expected result

The Quick Start is complete when:

- The validated firmware is programmed successfully.
- The device opens a Bluetooth Low Energy commissioning window.
- The commissioner accepts the onboarding code.
- The device joins the selected Thread network.
- The device appears in the Matter controller.
- The sample responds to the expected Matter command.
- The serial log shows the expected commissioned and operational state.

## Troubleshooting

| Problem | Action |
| --- | --- |
| Firmware checksum does not match | Download the package again and confirm that the correct board variant was selected. |
| Programmer cannot detect the board | Check the cable, power, debugger connection, USB permissions, and device selection. |
| No Bluetooth Low Energy advertisement is found | Reset the board or use the validated action to reopen the commissioning window. |
| QR code is rejected | Confirm that the QR code belongs to the exact firmware instance and that the device has been reset to the expected state. |
| Commissioning stops while configuring Thread | Confirm the Thread Border Router, dataset, local network, and controller compatibility. |
| Device was already commissioned | Remove it from the previous fabric or perform the validated factory-reset procedure. |
| Matter command has no physical effect | Confirm the correct device type, endpoint, LED mapping, and sample firmware. |
