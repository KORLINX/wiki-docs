# Introduction to Matter for NX Families

Matter is an IP-based application protocol for interoperable connected devices. In this tutorial series, an NX device is commissioned over Bluetooth Low Energy and then communicates as a Matter device over Thread.

This page provides the minimum terminology required before you begin. It is not a detailed protocol lesson.

:::caution
Validation scope
The workflow in this series targets NX15 and NX40 development platforms. The final hardware revision, board target, SDK version, sample configuration, and supported controller ecosystem must be confirmed by KORLINX R&D before publication.

## Matter in the NX workflow

The target workflow is:

1. An uncommissioned NX device advertises over Bluetooth Low Energy.
2. A Matter commissioner discovers the device and opens a secure commissioning session.
3. The commissioner provides operational credentials and the Thread Operational Dataset.
4. The NX device joins the Thread network.
5. A Matter controller communicates with the device over IPv6 and Thread.

Bluetooth Low Energy is used for commissioning. It is not the normal Matter application transport after the device has joined Thread.

## Components you need to recognize

| Component | Role in this series |
| --- | --- |
| NX Matter device | The device being built, flashed, commissioned, and controlled. |
| Commissioner | Adds the NX device to a Matter fabric. |
| Controller | Reads device state and sends Matter commands after commissioning. |
| Thread Border Router | Connects the Thread IPv6 mesh to the adjacent IP network. |
| Matter fabric | The trust domain that contains the commissioned Matter nodes. |
| CHIP Tool | A development controller used to commission and test Matter devices. |

One physical hub can perform more than one role. For example, a commercial hub can act as commissioner, controller, and Thread Border Router.

## Matter data model keywords

You do not need to understand the complete Matter data model before starting the practical tutorials. Keep these keywords available when you need to inspect an application or search the official documentation.

| Keyword | Short meaning |
| --- | --- |
| Node | An addressable Matter device or logical resource. |
| Endpoint | A functional part of a node. |
| Device Type | The standardized behavior assigned to an endpoint. |
| Cluster | A group of related functions. |
| Attribute | A state or configuration value. |
| Command | An action requested by a controller. |
| Event | A notable occurrence reported by a device. |

**Developer reference keywords:** `Matter data model`, `Matter Node`, `Endpoint 0`, `Device Type`, `Cluster`, `Attribute`, `Command`, `Event`
