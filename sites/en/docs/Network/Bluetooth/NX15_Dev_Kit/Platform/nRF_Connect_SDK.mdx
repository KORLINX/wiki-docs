# How to Use NX15 with nRF Connect SDK and Zephyr over SWD

This guide explains how to prepare **nRF Connect SDK and Zephyr RTOS** for the **NX15 Dev Kit**, connect an external **SEGGER J-Link** debug probe through **Serial Wire Debug (SWD)**, build a KORLINX sample, and flash it to the board.

![NX15 Dev Kit connected to an external J-Link through SWD](/img/bluetooth/nx15/platform/nx15-ncs-swd-overview.png)

<p style={{ textAlign: 'center', marginTop: '0.5rem' }}>
  <em>Connection overview. The dashed SWD path is conceptual. The separate USB connection from the computer to J-Link is omitted.</em>
</p>

## Understand the development platform

The NX15 Series is based on the Nordic **nRF54L15**. The NX15 Dev Kit provides an SWD interface for programming and debugging, plus an onboard **USB-to-UART interface** for serial communication.

**nRF Connect SDK** is Nordic's software development kit. Its Zephyr-based workflow combines the **Zephyr RTOS**, drivers, Nordic libraries, and development tools. Zephyr provides the operating system and hardware/software configuration framework used by the application.

<div className="spec-table-wrapper">

| Component | Role |
| --- | --- |
| Visual Studio Code | Editor and development environment |
| nRF Connect for VS Code | SDK setup and application development tools |
| nRF Connect SDK | Nordic software and the Zephyr-based development workspace |
| Matching toolchain | Compiler and tools associated with the selected SDK release |
| NX15 board support | `nx15/nrf54l15/cpuapp` from KORLINX NX-Zephyr-Samples |
| External J-Link probe | Host-to-target debug connection through SWD |

</div>

The board's USB Type-C connection supports power and the USB-to-UART interface. For this guide, the programming and debugging path is the **external J-Link connected to SWD**.

## Before you begin

### Required hardware

<div className="spec-table-wrapper">

| Item | Requirement |
| --- | --- |
| NX15 Dev Kit | Board with accessible, identified SWD connections |
| SEGGER J-Link | Probe supporting nRF54L15 and the target's I/O voltage |
| SWD cable or adapter | Compatible with the probe connector and NX15 SWD interface |
| Board USB cable | Data-capable USB Type-C cable for board power and the serial interface |
| Probe USB cable | Cable matching the J-Link's host USB connector |
| Computer | Host supported by the selected SDK release |

</div>

A bare NX15 module needs a suitable carrier providing power, ground, and access to SWD signals. This guide uses the Dev Kit.

### Required software and board information

- [Visual Studio Code](https://code.visualstudio.com/download).
- Nordic's **nRF Connect for VS Code** extension and its companion extensions.
- **nRF Connect SDK v3.3.1 or later** and the toolchain with the same version number. The illustrated workflow uses v3.4.0 for both.
- [SEGGER J-Link Software and Documentation Pack](https://www.segger.com/downloads/jlink/), using the version recommended for the selected Nordic environment.
- [KORLINX NX-Zephyr-Samples](https://github.com/KORLINX/NX-Zephyr-Samples) and the pinout for the actual board revision.

:::note
NX15 board support
KORLINX provides the NX15 board definition in [NX-Zephyr-Samples](https://github.com/KORLINX/NX-Zephyr-Samples). Use target `nx15/nrf54l15/cpuapp` with **nRF Connect SDK v3.3.1 or later**. Always use the SDK and toolchain with the same version number. The repository documents v3.3.1 as its tested baseline, while the screenshots in this guide show a successful build-and-flash workflow with SDK v3.4.0 and toolchain v3.4.0. Confirm that the board revision in use matches the repository's NX15 definition and released pinout.
:::

## Step 1 — Install the Nordic VS Code extension

1. Install Visual Studio Code for your operating system.
2. Open **Extensions** from the Activity Bar.
3. Search for **nRF Connect for VS Code**.
4. Select **nRF Connect for VS Code** published by **Nordic Semiconductor**, then select **Install**.
5. Reload VS Code if prompted and open **nRF Connect** from the Activity Bar.

The extension provides the development interface. Install the SDK and toolchain separately through its setup workflow.

See Nordic's [nRF Connect for VS Code installation guide](https://docs.nordicsemi.com/r/bundle/nrf-connect-vscode/page/get_started/install.html) for host prerequisites.

## Step 2 — Install the toolchain

1. Open **nRF Connect** from the Activity Bar.
2. Under **WELCOME**, select **Manage toolchains**.
3. Select **Install toolchain**.
4. Select **v3.3.1 or later** and wait for installation to finish. The screenshots use **v3.4.0**.

![Open Manage toolchains and select Install toolchain](/img/bluetooth/nx15/nrf-connect-sdk/install-toolchain-1.png)

![Select nRF Connect SDK Toolchain v3.4.0](/img/bluetooth/nx15/nrf-connect-sdk/install-toolchain-2.png)

<p style={{ textAlign: 'center', marginTop: '0.5rem' }}>
  <em>The screenshots use toolchain v3.4.0. Record the selected version and install the SDK with the same version number.</em>
</p>

## Step 3 — Install nRF Connect SDK

1. Under **WELCOME**, select **Manage SDKs**.
2. Select **Install SDK**.
3. Select **nRF Connect SDK**. Do not select the Bare Metal workflow for this guide.
4. Select the same version installed in Step 2. The screenshots use **v3.4.0 LTS**.
5. Choose the SDK installation directory and confirm the location.
6. Wait until installation finishes, then confirm that the SDK and toolchain show the same version number in the nRF Connect view.

![Choose the SDK installation location](/img/bluetooth/nx15/nrf-connect-sdk/install-sdk-4.png)

<p style={{ textAlign: 'center', marginTop: '0.5rem' }}>
  <em>Install the Zephyr-based nRF Connect SDK and use the same version as the installed toolchain.</em>

Use nRF Connect SDK **v3.3.1 or later**. Do not mix SDK and toolchain versions. The **nRF Connect SDK Bare Metal** option uses a different development workflow and is outside this guide.

Follow the official [first-time SDK and toolchain installation steps](https://docs.nordicsemi.com/r/bundle/nrf-connect-vscode/page/get_started/quick_setup.html/installing-sdk-and-toolchain-for-the-first-time).

## Step 4 — Install the J-Link software

1. Check Nordic's [extension prerequisites](https://docs.nordicsemi.com/r/bundle/nrf-connect-vscode/page/get_started/install.html/extension-prerequisites) for the selected environment.
2. Download the recommended J-Link Software and Documentation Pack for your operating system.
3. Run the installer and complete the applicable USB driver or host-permission setup.
4. Restart VS Code if required by the installer.

Use a probe and J-Link software combination that supports **nRF54L15**. Host setup differs between Windows, macOS, and Linux; follow the installer and Nordic release instructions.

## Step 5 — Identify the NX15 SWD connections

Before attaching the probe, locate the board's **SWD interface** and check the connector orientation against the schematic or pinout for your NX15 revision.

![NX15 SWD header labels and an external J-Link cable illustration](/img/bluetooth/nx15/platform/nx15-ncs-jlink-connection.png)

<p style={{ textAlign: 'center', marginTop: '0.5rem' }}>
  <em>Supplied NX15 connection illustration. Confirm the labeled header order against your board schematic; the ribbon cable represents an adapter with matching signal connections.</em>
</p>

The illustration labels NRESET, SWDCLK, GND, SWDIO, and 3V3. The available Hardware page does not independently confirm their physical order on this header. A standard J-Link connector must use a compatible adapter; the illustrated cable does not establish pin-to-pin compatibility.

The table below describes **logical signal connections**, not physical connector pin numbers.

<div className="spec-table-wrapper">

| J-Link signal | NX15 connection | Purpose |
| --- | --- | --- |
| VTref | Confirmed target I/O supply reference (3V3 in the supplied illustration) | Lets the probe sense the target's logic voltage |
| GND | GND | Shared ground reference |
| SWDIO | SWDIO | Bidirectional debug data |
| SWCLK | SWDCLK | Debug clock |
| nRESET, if used | NRESET | Target reset; connect when required by the board/adapter instructions |

</div>

Basic SWD communication uses SWDIO and SWCLK. No SWO connection is required for this setup.

:::caution
Check the actual connector
J-Link connector layouts and adapters differ. Match signals using the documentation for your probe, adapter, and NX15 board revision. Do not infer SWD pin order from the J3/J4 expansion-header tables or from an illustration.
:::

:::note
VTref is a voltage reference
VTref is an input to J-Link; it does not power the target. Connect it to the confirmed target I/O supply reference. Do not connect the probe's optional 5 V power output to the NX15 3.3 V rail.
:::

See SEGGER's [SWD interface description](https://www.segger.com/products/debug-probes/j-link/technology/interface-description/) and [VTref explanation](https://kb.segger.com/VTref).

## Step 6 — Connect J-Link to NX15

1. Disconnect USB power from the NX15 Dev Kit and unplug J-Link from the computer. Disconnect any other target power source before wiring.
2. Check the SWD connector orientation and the signal labels for the actual board revision.
3. Attach the compatible SWD cable or adapter. For individual wires, connect **GND**, **SWDIO**, **SWCLK**, and **VTref** according to the signal table above. Add **nRESET** if required by your board/adapter instructions.
4. Check that the connections are secure, correctly aligned, and free of shorts. Keep individual debug wires short.
5. Connect the NX15 Dev Kit's USB Type-C port to the computer to power the board.
6. Connect J-Link's host USB port to the computer.

The setup now has two separate host connections: USB to the NX15 Dev Kit for board power and its serial interface, and USB to J-Link for the SWD debug path.

### Connection checklist

- nRF Connect SDK v3.3.1 or later and the toolchain with the same version number are installed.
- The required J-Link driver is installed.
- The probe and NX15 share ground.
- SWDIO and SWCLK connect to the correct target signals.
- VTref connects to the target I/O supply reference.
- The cable orientation matches the confirmed board pinout.
- The NX15 Dev Kit is powered and J-Link is connected to the computer.

## Step 7 — Clone KORLINX NX-Zephyr-Samples

1. In the nRF Connect view, select **Open terminal**.
2. Choose the terminal profile that matches the installed SDK version if prompted.
3. Change to the directory where you keep development repositories.
4. Clone the KORLINX repository:

```bash
git clone https://github.com/KORLINX/NX-Zephyr-Samples.git
```

The cloned repository contains the NX15 board definition and the sample applications used in the following steps.

## Step 8 — Open a sample application

1. In the nRF Connect view, select **Open an existing application**.
2. Browse to `NX-Zephyr-Samples/samples`.
3. Select the sample folder to build. Start with `hello` to verify the toolchain and programming path.
4. Select **Open**.

## Step 9 — Add the NX15 build configuration

1. Under **Applications**, locate the opened sample and select **Add build configuration**.
2. Select the installed SDK and toolchain pair with matching version numbers.
3. Set the board target to `nx15/nrf54l15/cpuapp`.
4. Enable **Sysbuild**.
5. Add the repository root as an extra Zephyr module:

```text
-DZEPHYR_EXTRA_MODULES=/absolute/path/to/NX-Zephyr-Samples
```

6. Select **Generate and Build** to create the build configuration and compile the sample.

Use an absolute repository path. The build system needs the repository as an extra Zephyr module to find the KORLINX board definition.

![Select matching SDK and toolchain versions and configure the board target](/img/bluetooth/nx15/nrf-connect-sdk/build-configuration-1.png)

![Enable Sysbuild and generate the NX15 build configuration](/img/bluetooth/nx15/nrf-connect-sdk/build-configuration-2.png)

![Confirm that the Build section and sample name appear](/img/bluetooth/nx15/nrf-connect-sdk/build-configuration-3.png)

<p style={{ textAlign: 'center', marginTop: '0.5rem' }}>
  <em>Select matching SDK and toolchain versions, use the NX15 board target, enable Sysbuild, and confirm that the build configuration appears.</em>

## Step 10 — Build the sample

1. Expand the sample's build configuration.
2. Under **Actions**, select **Build**.
3. Wait for the terminal to report that the build completed.
4. Confirm that the output identifies the board as `nx15/nrf54l15/cpuapp`.

![Successful NX15 sample build in nRF Connect for VS Code](/img/bluetooth/nx15/nrf-connect-sdk/build-successfully.png)

<p style={{ textAlign: 'center', marginTop: '0.5rem' }}>
  <em>The build completes and generates the firmware for the NX15 application core.</em>
</p>

## Step 11 — Flash the sample through J-Link

1. Confirm that the NX15 Dev Kit is powered and J-Link remains connected through SWD.
2. Under **Actions**, select **Flash**.
3. If the device picker appears, select the serial number that belongs to the connected J-Link probe, then select **OK**.
4. Wait while the extension programs and verifies the image.

![Select the connected J-Link probe before flashing NX15](/img/bluetooth/nx15/nrf-connect-sdk/select-jlink.png)

![Successful NX15 firmware flash output](/img/bluetooth/nx15/nrf-connect-sdk/flash-successfully.png)

<p style={{ textAlign: 'center', marginTop: '0.5rem' }}>
  <em>The flash operation is complete when the terminal reports that the selected board was flashed successfully.</em>
</p>

:::note
Flash runner
The NX15 board definition uses `nrfutil` as its default flash runner and also supports J-Link. The device picker may show more than one connected probe. Select the serial number of the J-Link wired to the NX15 Dev Kit.
:::

## Step 12 — Verify the application output

1. Keep the NX15 Dev Kit connected through USB Type-C. Open a serial terminal and select the USB serial port reported by the operating system, such as `COMx` on Windows or `/dev/ttyUSBx` on Linux.
2. Configure the terminal for **115200 baud**.
3. Reset the board if output does not appear immediately.
4. Confirm that the `hello` sample prints its expected console messages.

Expected output begins with the selected board target and then prints one `printk` tick and one log tick per second:

```text
Korlinx NX hello sample on nx15/nrf54l15/cpuapp
<inf> hello: logging is up
printk tick #0
<inf> hello: LOG tick #0
```

The exact log prefix and timestamp formatting can vary with the SDK configuration.

The build-and-flash workflow is now complete. To run another sample, open its directory, create the same NX15 build configuration, and review its README for hardware or configuration requirements.

## NX15 code examples

The [KORLINX NX-Zephyr-Samples repository](https://github.com/KORLINX/NX-Zephyr-Samples) supplies the NX15 board definition and sample applications. Use nRF Connect SDK **v3.3.1 or later**, pair it with the toolchain of the same version, and select the `nx15/nrf54l15/cpuapp` target. The repository documents v3.3.1 as its tested baseline.

The equivalent command-line workflow from an initialized nRF Connect SDK terminal is:

```bash
west build -b nx15/nrf54l15/cpuapp /absolute/path/to/NX-Zephyr-Samples/samples/hello -- \
  -DZEPHYR_EXTRA_MODULES=/absolute/path/to/NX-Zephyr-Samples
west flash
```

Replace `hello` with another sample from the table and review that sample's README for prerequisites and expected output.

## Troubleshooting

<div className="spec-table-wrapper">

| Symptom | What to check |
| --- | --- |
| NX15 is missing from the board list | Confirm that `ZEPHYR_EXTRA_MODULES` points to the absolute path of the `NX-Zephyr-Samples` repository root, then recreate the build configuration |
| Build configuration fails or tools are not found | Confirm that both the SDK and toolchain are v3.3.1 or later and use the same version number |
| J-Link does not appear in the device picker | Check the J-Link USB connection, installed J-Link software, target power, shared ground, SWDIO, SWCLK, and VTref |
| More than one probe appears | Select the serial number printed on or reported for the J-Link connected to the NX15, or disconnect unused probes |
| Flash fails after a successful build | Recheck target power and SWD wiring, then retry **Flash** with the correct probe selected |
| No `hello` output appears | Open the NX15 USB serial port at 115200 baud and reset the board; confirm that another application is not using the port |

</div>
