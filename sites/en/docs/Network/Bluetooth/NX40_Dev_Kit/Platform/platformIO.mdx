# How to Use NX40 with PlatformIO

Use **PlatformIO IDE in Visual Studio Code** to organize an Arduino-framework project for the **KORLINX DEV-NX40** development board. This guide follows the setup sequence in the Seeed Studio PlatformIO reference: install the IDE, prepare a project, and configure its development platform. It adds NX40-specific prerequisites, example code, and verification steps.

:::info
NX40 integration prerequisite
The supplied NX40 wiki documents the KORLINX Arduino BSP, but does not identify a verified PlatformIO platform package, board manifest, or tested upload configuration. The steps below describe the workflow once compatible NX40 PlatformIO support is available. The `platformio.ini` example contains placeholders and is not a ready-to-build configuration.

For the currently documented Arduino setup, see [NX40 with Arduino](./Arduino.mdx).
:::

## What you will build

Prepare a PlatformIO project containing an Arduino application that blinks the NX40 red user LED every 500 ms. An optional second application checks native USB Serial output.

## Before you begin

### Required hardware

| Item | Requirement |
| --- | --- |
| Development board | DEV-NX40 with the NX40-compatible bootloader required by the selected USB upload integration |
| USB cable | Data-capable USB Type-C cable |
| Host computer | Windows, macOS, or Linux computer supported by the selected PlatformIO tools |
| Optional debug probe | Required for bootloader installation/recovery, or an explicitly configured SWD workflow |

A bare NX40 module needs a carrier board providing power, programming access, and the required circuitry. Review the [DEV-NX40 hardware guide](../Hardware.mdx) before connecting external devices.

### Required software

- [Visual Studio Code](https://code.visualstudio.com/).
- [PlatformIO IDE for VS Code](https://docs.platformio.org/en/latest/integration/ide/vscode.html).
- NX40-compatible PlatformIO board and framework integration supplied or approved by KORLINX.
- Git if the integration installs packages from Git repositories.
- USB drivers, serial-port permissions, and uploader dependencies specified by that integration.

PlatformIO Core is included with the VS Code extension; a separate Core installation is unnecessary for this IDE workflow. Follow PlatformIO's installation documentation for host-specific requirements.

## Step 0: Obtain NX40 PlatformIO support

Confirm these items before preparing a build:

| Item | Information required |
| --- | --- |
| Development platform | Package specification or repository, with a supported version or pinned revision |
| Board | Exact PlatformIO board ID and matching manifest |
| Arduino framework | Compatible core package containing the NX40 variant and required libraries |
| Build configuration | Compiler options, linker script, and application memory layout |
| Bootloader / SoftDevice | Versions and reserved memory regions expected by the build and uploader |
| USB upload | Supported protocol, uploader, reset procedure, and USB port identification |
| Hardware mapping | LED, button, UART, I2C, SPI, and module-specific external Flash settings |

The existing Arduino guide identifies **KXBoards nRF52**, **NX40 nRF52840**, and FQBN `korlinx:nrf52:nx40`. These are Arduino identifiers; the FQBN is not a PlatformIO board ID. Adding the Arduino Boards Manager URL also does not install a PlatformIO board.

The [Seeed reference](https://wiki.seeedstudio.com/xiao_nrf52840_with_platform_io/) uses a Seeed development platform and XIAO board ID. Those settings describe XIAO hardware. Use the approved NX40 integration for this product.

:::note
Custom board integration
PlatformIO supports project-local board manifests in the `boards` directory. A manifest describes board settings, but it must work with the platform's framework builder, variant files, linker configuration, and uploader. A JSON file containing only the MCU type does not establish NX40 compatibility.

See [PlatformIO custom embedded boards](https://docs.platformio.org/en/latest/platforms/creating_board.html).
:::

## Step 1: Install PlatformIO IDE

1. Install Visual Studio Code.
2. Open **Extensions** in the Activity Bar.
3. Search for the official **PlatformIO IDE** extension and install it.
4. Wait for initialization to finish; reload VS Code if requested.
5. Open **PlatformIO Home**.
6. Open a PlatformIO terminal and check the included Core:

```bash
pio --version
```

Follow the [official installation guide](https://docs.platformio.org/en/latest/integration/ide/vscode.html) if initialization fails.

## Step 2: Prepare an NX40 project

If KORLINX supplies a starter project, open its folder with **File > Open Folder**. Keep its board manifests, scripts, and configuration files together.

If the approved NX40 board is available in PlatformIO Home:

1. Select **New Project**.
2. Name the project `nx40_blink`.
3. Select the exact NX40 board provided by the integration.
4. Select **Arduino** as the framework.
5. Select a project location and finish creation.

If the board is supplied as a local manifest, follow the integration's installation instructions and place it in the project's `boards` directory when required. Do not substitute another manufacturer's board to complete the wizard.

| Project item | Purpose |
| --- | --- |
| `platformio.ini` | Platform, board, framework, build, upload, and monitor settings |
| `src/main.cpp` | Application source |
| `include/` | Project headers |
| `lib/` | Project-local libraries |
| `boards/` | Custom manifests, when required by the NX40 integration |
| `.pio/` | Generated build files and project dependencies |

## Step 3: Configure platformio.ini

Use the `platformio.ini` delivered with the NX40 integration as your starting point. The following illustrates the relevant fields:

```ini
; TEMPLATE ONLY: replace both REQUIRED_* values before use.
[platformio]
default_envs = nx40

[env:nx40]
platform = REQUIRED_NX40_PLATFORM_SPEC
board = REQUIRED_NX40_BOARD_ID
framework = arduino
monitor_speed = 115200
```

`nx40` is a local environment name chosen for this tutorial. It does not register a board. Replace `REQUIRED_NX40_PLATFORM_SPEC` and `REQUIRED_NX40_BOARD_ID` with the actual values supplied by the integration.

Keep any required `platform_packages`, `build_flags`, `extra_scripts`, and upload settings from the approved starter project. A framework package override must remain compatible with the platform's build scripts; pointing a package override at the Arduino BSP repository alone is not a validated integration.

Save the file and allow PlatformIO to resolve its dependencies. Confirm that the build configuration uses the NX40 variant and its approved flash layout before uploading.

## Step 4: Create the Blink application

Open `src/main.cpp` and replace its contents with:

```cpp
#include <Arduino.h>
#include <Adafruit_TinyUSB.h>

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_BUILTIN, LED_STATE_ON);
  delay(500);

  digitalWrite(LED_BUILTIN, 1 - LED_STATE_ON);
  delay(500);
}
```

PlatformIO compiles this as a C++ source file, so include `Arduino.h` explicitly. The code uses the NX40 BSP's LED alias and active-level definition. The supplied Arduino guide maps `LED_BUILTIN` to the red LED on P0.11 and describes it as active-low.

The TinyUSB include follows the existing NX40 Arduino examples. The selected framework integration must provide this library and the NX40 definitions; installing an unrelated core does not ensure that these symbols exist.

## Step 5: Build the application

1. Select the `nx40` environment.
2. Run **PlatformIO: Build**, or use the PlatformIO terminal:

```bash
pio run -e nx40
```

3. Wait for the build to complete successfully.
4. Check that the log identifies the approved NX40 board and framework packages.

Compilation confirms that the selected software configuration builds. LED behavior, USB enumeration, and bootloader compatibility require a hardware test.

## Step 6: Connect and upload

This section assumes the approved integration provides USB DFU upload compatible with the NX40 bootloader.

1. Connect DEV-NX40's native nRF52840 USB interface with a data-capable cable.
2. List available serial devices:

```bash
pio device list
```

3. Identify the NX40 native USB port. The FTDI bridge is a separate hardware UART interface.
4. Close serial monitors that may hold the upload port open.
5. Run **PlatformIO: Upload**, or:

```bash
pio run -e nx40 -t upload
```

If automatic port selection is unsuitable, specify the actual port:

```bash
pio run -e nx40 -t upload --upload-port YOUR_NX40_PORT
```

Replace `YOUR_NX40_PORT` with the port reported by your computer. The integration determines whether it selects the application port or bootloader port and how reset/re-enumeration is handled.

The existing NX40 Arduino guide documents double-pressing Reset within 500 ms, or holding SW2 while pressing Reset, to enter the bootloader. Use those methods when required by the approved upload procedure. Automatic 1200-bps reset in Arduino IDE does not prove that a PlatformIO uploader implements the same behavior.

If the bootloader is missing, follow [bootloader installation or recovery](./Arduino.mdx#step-0-install-or-recover-the-bootloader-if-needed) before USB upload. That procedure can erase existing firmware and stored data.

{/* IMAGE NOTE [NX40-PIO-06]: Show the actual DEV-NX40 connected by native USB and an actual successful PlatformIO upload. Label the connector only after confirming its routing. */}

## Step 7: Confirm the LED result

After successful upload and reset, the expected application behavior is:

- The red user LED turns on for approximately 500 ms.
- It turns off for approximately 500 ms.
- The cycle repeats continuously.

Check the user LED controlled by the application. Power or charging indicators alone do not verify Blink. If upload succeeds but the LED does not blink, review the NX40 variant, polarity, application flash layout, and board revision.

## Optional: Verify USB Serial

Replace `src/main.cpp` with:

```cpp
#include <Arduino.h>
#include <Adafruit_TinyUSB.h>

void setup() {
  Serial.begin(115200);
  const uint32_t started = millis();
  while (!Serial && millis() - started < 3000) {
    delay(10);
  }
}

void loop() {
  if (Serial) {
    Serial.println("KORLINX NX40 PlatformIO is running");
  }
  delay(1000);
}
```

Build and upload again. After USB re-enumeration, select the application port and open **PlatformIO: Serial Monitor**, or run:

```bash
pio device monitor --port YOUR_NX40_PORT --baud 115200 --dtr 1
```

The DTR option supports the sketch's `Serial` connection check. Expected output is approximately one line per second:

```text
KORLINX NX40 PlatformIO is running
```

`Serial` uses native USB CDC in the documented NX40 Arduino workflow. `Serial1` uses the hardware UART. Select the native USB application port for this example; its output will not appear on the FTDI UART port.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| NX40 is absent from the project wizard | Install the approved integration or open its starter project; an Arduino Boards Manager installation is separate |
| Unknown board or package error | Replace template values, confirm the exact board ID, and check manifest/package installation |
| `LED_STATE_ON` is undefined | Confirm that the NX40 Arduino variant is selected |
| TinyUSB header is missing | Confirm that the integration includes the BSP's required libraries and submodules |
| Linker or SoftDevice-related errors | Check framework, compiler, linker script, and reserved memory compatibility |
| No upload port | Check the data cable, native USB routing, bootloader, drivers, and serial permissions |
| Upload fails after entering the bootloader | Check the new port and the uploader's reset/port-discovery behavior |
| Uploader is missing | Install the dependency required by the approved integration; Arduino IDE tools may not be available to PlatformIO |
| Upload succeeds but no Blink | Check the LED mapping, polarity, board revision, and image layout |
| Serial Monitor is blank | Select the application USB port, assert DTR, reopen after enumeration, and confirm USB CDC support |
